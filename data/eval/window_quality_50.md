# 50 组 Context Unit 切窗评测

评测对象：`data/samples/context_units_eval_50.jsonl`  
宣称规则：前 8 后 3 + 20 分钟合并  
实测规则：几乎是「按锚点截断到 12 条消息」，**20 分钟合并基本没有生效**。

## 1. 总体结论

| 指标 | 结果 |
|---|---|
| 样本数 | 50 |
| 消息数 = 12 | 49 / 50（`cu_sample_001` 仅 4 条） |
| 讨论区短窗（跨度 ≤ 15 分钟） | 16 / 50 |
| 广播流超时窗（跨度 ≥ 2 小时） | 30 / 50 |
| 跨交易时段硬粘连（盘前/盘中/盘后/隔夜） | 22 / 50 |
| 单 CU 多独立事件（应拆） | 28 / 50 |
| 前 8 噪音过重（讨论区闲聊） | 8 / 50 |
| 后 3 截断导致动作链不完整 | 6 / 50 |
| 图片占位无文本、标的缺失 | 11 / 50 含 `[图片]` |

**一句话：固定 12 条上限在「赵哥独白频道」上把半天到两天的多标的操作揉成一个 CU；在「讨论区」上前 8 又太宽，灌进大量无关群聊。20 分钟合并没有按时间落地。**

全量 7.5 万条若沿用这套切窗，L2 envelope 会系统性出现：多 ticker 动作堆叠、会话串台、训练样本标签冲突。必须先改切窗再跑全量抽取。

## 2. 时间字段缺陷（先修，否则 20 分钟无法计算）

每条 `dialogue_messages[].time` 只有 `HH:MM:SS`，日期只在 CU 级 `et_timestamp`。

后果：

- 无法在 CU 内部判断是否跨日（`23:50 → 00:04` 是 +14 分钟还是 +24 小时）
- `cu_sample_003` 出现 `01:41` 与 `21:10` 两簇，中间像隔了整个交易日
- `et_timestamp` 与窗口内最后一条时间并不总一致，不能当锚点时刻

**工程必改：** 每条消息写完整 `created_at_et` ISO-8601（含日期）。切窗、合并、session 标注全部基于这条时间戳，禁止只用当日时钟。

同时给每条消息打 `session`：

| session | ET 规则（美股） |
|---|---|
| `overnight` | 20:00–04:00 |
| `premarket` | 04:00–09:30 |
| `regular` | 09:30–16:00 |
| `afterhours` | 16:00–20:00 |
| `weekend` | 周六日 |

**硬切规则：session 变化 ⇒ 必须新开 CU**，即使消息间隔不到 20 分钟（跨 session 的 15 分钟和同 session 的 15 分钟语义完全不同）。

## 3. 分类型评测

### A. 广播独白（期权/forum_feed/股票记录）— 001–031, 039, 041, 045, 049

特征：几乎全是 `role=kol`，12 条消息拉满，时间跨度 1 小时到 29 小时。

| 样本 | 跨度（按 clock 粗算） | 问题 | 建议切法 |
|---|---|---|---|
| 001 | 3h55，仅 4 条 | 00:04 减仓与 03:27 再减仓中间真空 | 按 20–25 分钟 gap 拆成 2–3 个 CU |
| 002 | 4h18 | TSLL/CONL/RDDT/QQQ/HIMS/特朗普讲话 6 件事 | 按 ticker 突发 + gap 拆 4–6 个 |
| 003 | 两簇 32min + 34min | 跨 session 粘连 | 两簇各一个 CU |
| 004 | 66min | 早盘支撑位扫描，尚可视为一份 watchlist | 保留为 `cu_type=watchlist`，不要再往后拼 |
| 005–008 | 2h–20h | 盘中执行 + 盘后计划 + 次日复盘粘在一起 | session 硬切 |
| 015 | 8h | 置顶股单（playbook）和盘中执行混在一个 CU | 长股单单独 `cu_type=playbook` |
| 016 | 12h | 尾盘卡机制一组 + 次日夜盘预警一组 | 硬切 |
| 025 | 期权短脉冲 + 隔日残句 | 「5 元上限清仓」无标的 | 短脉冲可留；缺 ticker 的残句不要并进来 |
| 010 末 4 条 | NVDA 财报出货 | 与当天早盘 TSLL/ORCL 不是同一事件 | 财报簇单独 CU |

广播频道 **不要用前 8 后 3**。正确规则：

1. 只取 KOL 自己的帖
2. `gap > 25min` 或 `session` 变化 → 切开
3. 同一 25 分钟簇内，若出现「新事件标记」（财报/讲话开始/「置顶股单」/「更新一半仓位」）→ 再切
4. 单簇最多 8 条 KOL 文本（图片不计入）
5. 一条超长置顶股单 = 独立 playbook CU，不与后续执行合并

### B. 讨论区问答 — 032–038, 040, 042–044, 046–048, 050

特征：peer + kol 混排，真实跨度大多 2–8 分钟。这才是前 N 后 M 的用武之地。

| 样本 | 跨度 | 质量 | 问题 |

| 036 | 2min | 好 | 「盘前是机制」完整常识块 |
| 037 | 2min | 好 | 访华高点/承受力 |
| 038 | 7min | 好 | NKE 超跌反弹 |
| 040 | 4min | 弱 | KOL 只回了 Space 一句，窗口里大量无关图 |
| 042 | 1.5min | 好 | BTC 无点位 + GOOGL 缺口 |
| 043 | 5min | 好 | SOXS 不能买 |

讨论区规则应改成：

- 锚点 = KOL 非噪声发言（排除纯 `[图片]` / 单表情）
- 向前取 **3 条非噪声**，向后取 **2 条**
- 3 分钟内的连续 KOL 回复合并进同一 CU
- 前向遇到「新的无关 peer 闲聊超过 2 条」停止扩展
- 不要强行凑满 8+3

## 4. 20 分钟合并：该留的与该丢的

**该合并**

- 同一 session、间隔 ≤ 20 分钟的连续 KOL 报价（例：005 里 21:40–21:54 的 UPST/TSLL/ORCL/CRWV/NVDL/OPEN 一串早盘指令）
- 讨论区 3 分钟内的多段短回复（036、037、042）
- 同一笔交易的「报价 → 确认成交价」（019：18.45–18.6 出 → 18.42 出了）

**不该合并**

- 跨 session（盘中指令 + 盘后股单 + 次日复盘）
- 间隔 > 25 分钟，即使都是同一标的（001 的 21.05 减仓 与 3 小时后的 21.7 再减，中间市场已变）
- playbook 长帖 + 数小时后的执行回执
- 「图片 + 无文字」与前后无关报价

经验阈值（按这 50 条调）：

```
SOFT_MERGE_GAP = 20min   # 同 session 可合并
HARD_SPLIT_GAP = 25min   # 超过必切
MAX_KOL_MSGS   = 8       # 广播簇上限
QA_BEFORE      = 3
QA_AFTER       = 2
QA_KOL_MERGE   = 3min
```

20 与 25 不要再加大。这批样本里 45–90 分钟的簇已经在混「计划」和「成交」。

## 5. 对全量 7.5 万条的落地顺序

1. 补齐每条消息的 `created_at_et` + `session`
2. 频道分流：`broadcast`（KOL≥80%）vs `qa`（peer≥30%）
3. 规则切窗（上面的 gap/session），**先不跑 LLM**
4. 统计：CU 数、中位时长、中位消息数、跨 session 比例。目标：跨 session < 2%，广播 CU 中位时长 8–15 分钟
5. 再对切好的 CU 跑 L2 抽取
6. 用本目录金标抽 50 条做回归，再铺开

不要在当前 12 条硬切窗口上直接抽 7.5 万。抽出来的 envelope 无法回放到单笔交易。
