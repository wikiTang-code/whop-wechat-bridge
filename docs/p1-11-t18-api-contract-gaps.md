# T18 预审：只读 API vs 现网 frontend 契约缺口（Cursor 并行交付）

> 基线：`d7a3ba9`；对照 `server.js` + `public/app.js` vs `monitoring/readonly-api-router.js`。  
> **用途**：给 Gemini T18 直接改；未对齐前切双进程会导致看板白屏/空列表。

## 结论

当前 `readonly-api-router.js` **不能替代** 单体看板读面：形状键名错误、过滤能力缺失、归属清单中的只读路由大量未挂载。

---

## A. 形状不兼容（必改，否则白屏）

对照 `public/app.js` 实际取值：

| 路径 | 现网 (`server.js`) | 只读路由现状 | Frontend 期望 | 风险 |
|---|---|---|---|---|
| `GET /api/channels` | `{ success, data: [...] }` | `{ success, channels: [...] }` | `result.data` | **频道列表空** |
| `GET /api/reports` | `{ success, data, total }` | `{ success, reports }`（无 `total`） | `result.data` + `result.total` | **报告页白屏** |
| `GET /api/news-summaries` | `{ success, summaries }` | `{ success, data }` | `data.summaries` | **资讯列表空** |
| `GET /api/gpu/status` | `{ success, data: global.gpuLock }` | `{ success, isLocked, owner, note }` | 若有调用方读 `data` | **形状漂移** |
| `GET /api/messages` | `{ success, data, total }` | `{ success, data, total, limit, offset }` | `result.data` / `total` | 顶层键 OK；见 B |

`GET /api/speakers`：现网与只读均为 `speakers` 数组，**键名兼容**；但语义不同（见 B）。

---

## B. 行为缺口（过滤 / 语义）

### B1. `GET /api/messages`（P0）

Frontend 会传：`speakerMode`、`search`、`sector`、`strategy`、`startDate`、`endDate`、`msgType`、`channelId`。

现网走 `getMessages(...)`（`database.js`），含 `TARGET_SPEAKER_USER_IDS` 大 V / 群友模式。

只读路由：**忽略全部过滤参数**，仅 `ORDER BY created_at DESC LIMIT/OFFSET` → 看板筛选失效。

**建议**：只读进程直接复用 `getMessages`（`db-readonly` 打开的连接注入，或抽纯查询函数），勿手写简化 SQL。

### B2. `GET /api/speakers`

- 现网：DISTINCT + **过滤掉** `TARGET_SPEAKER_USER_IDS`（群友补全用）
- 只读：全量 sender + `count`/`last_seen`

键名可过，但补全列表会混入大 V。建议对齐过滤逻辑。

### B3. `GET /api/channels`

- 现网：`getDistinctChannels()` → `{ channel_id, channel_name }`（registry 补名）
- 只读：`GROUP BY` + `message_count` / `last_activity`

Frontend 用 `result.data` 做 autocomplete；对齐键名后字段可多不可少 `channel_id`/`channel_name`。

### B4. `GET /api/reports` / `news-summaries`

- reports：应走 `getReports`，返回 **含正文等完整列** 的 `data` + `total`
- news：应走 `getNewsSummaries`，返回 `summaries`（`SELECT *`），含 `summary_content`

只读路由当前 **漏掉 content 列**，列表即使键名修好也无法展开正文。

## C. 归属清单已列、只读路由未挂（看板依赖）

来自 `docs/p1-11-route-ownership.md` + `public/app.js` 实际 `fetch`：

| 优先级 | 路径 | Frontend 用途 |
|---|---|---|
| P0 | `GET /api/news-summaries/status` | 资讯页任务态 |
| P0 | `GET /api/messages/:id/context` | 消息上下文 |
| P0 | `GET /api/proxy-image` | 图片展示 |
| P0 | `GET /api/config` | 设置/上次同步时间 |
| P1 | `GET /api/persona/status` `/latest` | Persona 页 |
| P1 | `GET /api/news-summaries/latest` | 最新资讯 |
| P1 | `GET /api/quant/portfolio` `/positions` `/orders` | 量化页 |
| P1 | `GET /api/system/monitor` | 系统监控 |
| P2 | `GET /api/campaigns*` `/macro-events` `/zhao-positions` `/strategies` | 次要页 |

**原则**：优先 **委托现有 `database.js` / 现有 handler 逻辑**（只读连接），禁止为“看起来像”再写一套 SQL。

写操作继续由 `readonlyWriteBlockerMiddleware` → **403**（已满足）。

## D. T18 验收清单（给 Gemini）

1. 形状：channels=`data`；reports=`data`+`total`；news=`summaries`；gpu=`data`
2. messages 过滤参数行为与单体一致（至少 speakerMode/search/channelId/date）
3. 挂载 C 表 P0 路由；单测断言键名与 `public/app.js` 取值路径
4. 禁止改生产 `ecosystem.config.cjs`；不要求本轮上机
